# デバッグ記録 2026-10-28

固有魔法GP、従来形式の魔法、戦闘、配合、セーブ、戦闘UIを対象に調査しました。実ファイルを扱うテストは元のセーブをバイト単位で退避・復元します。ビルドは行っていません。

## 再現して修正した問題

| 問題 | 修正・確認 |
|---|---|
| 長いフレームで、GP弾が射程や寿命を超えた位置の敵に命中する | 移動時間を残り寿命で制限し、移動線分を射程境界で切ってから衝突判定。0.2秒のフレームを使うテストで確認 |
| 弾が外部から破棄されると発動セッションの弾数が減らず、やがて発動枠・プールを使い切る | OnDestroyでセッションと弾一覧から解除。破棄した弾を保持するプールも再生成可能 |
| 戦闘終了後・無効化中の実行基盤が新しい発動を受け付ける | 発動受付時に状態を検査。最初のイベントを予約できない場合も発動成功として扱わない |
| 使用可能な先頭枠が壊れていると、未解放の次枠を繰り上げて使用する | ランク上限を配列インデックスで判定し、壊れた枠は使用不可のまま位置を保持 |
| 壊れた隠しスロットを読み飛ばし、後ろの遺伝子が前のスロットへずれる | 読み込み時に空の位置を保持。該当する親の配合は失敗として扱い、個体を消費しない |
| 壊れた使用中の遺伝子を、保存時に無関係なランダム遺伝子へ置換する | 元のJSONを保持し、実行不可・継承不可として扱う |
| 未対応の遺伝子型バージョンをパースでき、その後のコンパイルで例外になる | バージョン・発現・現在の実行制約まで検証してから読み込み成功とする |
| 破損したセーブを読み込めないと、起動時にデモ初期データで上書きする危険がある | 読み込み失敗時は保存禁止とし、元ファイルを維持。設定画面に理由を表示し、失敗した再読み込みを成功と通知しない |
| 従来形式のAIが一時停止中に発動してMPを使う | 戦闘管理・AI・従来弾の更新を停止。一時停止中にMP・発動数・弾数が増えないテストを追加 |
| 分裂などの威力減衰が、子弾の毒・火傷の継続ダメージに反映されない | 継続ダメージにも継承した倍率と術者のダメージ補正を反映 |
| 子弾が親弾の実ダメージを使い回し、自分でダメージを与えずHPを吸収する | 命中イベントごとに実ダメージをリセット。範囲効果でも対象ごとに独立させる |
| 連鎖弾が既に命中した対象を選び、他の敵がいるのに照準を失う | 候補を選ぶ段階で過去の対象を除外 |
| 無効化された敵が「敵接近」の条件を満たす | 発動・条件分岐・対象選択・衝突・効果の適用で非アクティブな対象を除外 |
| 最大ノード数付近の部分木交叉で、安全上限の例外がそのまま伝わる | 交叉・発現・構造変異の候補を取り消し、元の構造を保持する |
| 戦闘中の魔法一覧が自動名・変更名を表示せず、使用不可の枠も「使用可能」と表示する | 実際の魔法名と使用不可状態を表示。戦闘HUDの回帰テストで確認 |

## 検証範囲

- 最終結果：Unity 6000.4.3f1でEditMode 67/67、PlayMode 54/54成功。
- 既存のEditMode/PlayModeテスト全体と、新しい再現・回帰テストを実行。
- ゲーム内時間120秒、48発の魔法を繰り返し発動する負荷テストを実行。弾オブジェクト256以下、待機イベント2048以下を維持し、発動停止後に動作中の弾・予約イベントが0になることを確認。
- 全18画面・4解像度の既存レイアウト検査を継続。
- 破損セーブと将来バージョンの保存拒否は、意図したエラー・警告としてテスト内で検証。
- 配布ビルド、実機ごとのフレーム時間測定、何時間もの連続運転、ゲームバランス全体の評価は今回の検証に含みません。
